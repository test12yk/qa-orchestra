1기능 요약

목적
첫 구매 전환율 개선을 위해 주문서에서 보유 쿠폰을 쓸 수 있게 한다.
대상
쿠폰을 보유한 로그인 회원, 일반 상품 주문
핵심 흐름
주문서 진입 → 최대 할인 쿠폰 자동 선택 → (변경 가능) → 쿠폰 할인 → 포인트 차감 → 결제 승인 → 쿠폰 사용 처리
QA 핵심
금액 계산(최소 금액·한도·절사), 동시 사용, 취소 시 복구 세 곳에 결함 위험이 몰려 있다.

7확인 질문

#질문물어볼 사람왜 중요한가답 오기 전 임시 가정관련
Q1최소 주문 금액 30,000원에 배송비가 포함되나요?PM · 프로모션운영경계값 TC와 개발 검증 로직이 달라짐정책 기준(배송비 포함) — 운영 정책이 최신이고 개발도 같은 방식C1 · REQ-01
Q211/05 슬랙 결정(부분 취소·만료 쿠폰 미복구)을 기획서에 반영해 주실 수 있나요?PM공식 문서와 구현이 다르면 판정 근거가 없음슬랙 결정 기준으로 TC 작성, 판정 전까지 문서 반영 필수C2 · REQ-07 · 08
Q3결제 요약에서 쿠폰 할인 줄을 포인트보다 위에 두는 게 맞나요?디자이너사용자가 계산 순서를 오해할 수 있음표시는 디자인 가이드대로, 계산은 쿠폰 먼저C3 · REQ-06
Q4정률 할인 한도는 일괄 10,000원인가요, 쿠폰마다 다르게 설정하나요?프로모션운영 · 개발한도 경계값 TC의 기대 결과가 달라짐쿠폰별 설정값, 단 10,000원을 넘는 설정은 불가로 가정C4 · REQ-04
Q5같은 쿠폰으로 두 주문을 동시에 결제하면 어떻게 처리하나요?개발쿠폰 중복 사용 = 금전 손실먼저 승인된 주문만 적용, 나중 주문은 결제 실패 + 안내REQ-12

8테스트 범위 · 준비 사항

이번에 테스트하는 것

  • REQ-01 ~ REQ-12 전체
  • 할인 금액 계산 조합 (정률·정액 × 한도 × 포인트 × 제외 상품)
  • 동시 결제 시 쿠폰 중복 사용
  • 전체·부분 취소, 만료 쿠폰 취소

이번에 테스트하지 않는 것

  • 첫 구매 쿠폰 최소 금액 1만 원 — 💬 11/06 PM "다음 차수"
  • 쿠폰 발급·다운로드 기능 (기존 기능, 변경 없음)
  • 앱 푸시로 만료 안내 (기획 범위 밖)

테스트 계정 · 쿠폰

  • 정률 10% (한도 1만 원)
  • 정액 5,000원
  • 만료 D-1, D-3, D-4
  • 이미 만료된 쿠폰

상품 · 주문 데이터

  • 배송비 있는 상품 / 무료배송 상품
  • 상품권·e쿠폰 카테고리 상품
  • 합계 29,999 / 30,000 / 30,001원 조합
  • 부분 취소 가능한 다품목 주문

환경 · 도구

  • PG 테스트 결제 (승인·실패)
  • 동시 요청 재현 도구 (2기기 또는 스크립트)
  • 쿠폰 상태 조회 권한 (어드민·DB)
