# 2026.12 정기 릴리즈(샘플) 회귀 검토

**Fail 3개(결함 의심 1 · 확인 필요 2), 수동 9개 결과 없음 — 아직 판정 전** (남은 확인 뒤 판정)

- **RG-0018 전체 취소 포인트 미복구 (이번 변경으로 깨짐)**
  - 지난 회귀 Pass → 이번 Fail
  - 쿠폰 변경이 전체 취소를 건드렸고, SHOP-201 수정(10/24)도 취소 시 포인트 복구를 바꿨다
  - 버그 등록 → 개발 수정
- **RG-0011 포인트 초과 입력 거부 (TC가 명세와 다름?)**
  - 기존 케이스는 '보유분까지 사용', QA 서버 명세는 '400 거부'
  - 기획에 어느 쪽이 정책인지 질문
- **RG-0020 부분 취소 배송비 미차감 (환경?)**
  - QA 서버가 무료배송 기준을 계산하지 않아 조건이 안 만들어졌을 수 있다
  - 개발 확인 뒤 스테이지에서 수동 확인
- **수동 9개 결과 없음**
  - RG-0001·0009·0012·0013·0015·0016·0021·0022·0025
  - 테스터 실행 뒤 다시 검토
- **운영 결함 5건**
  - 회귀 편입 후보 3(SHOP-201 Critical · SHOP-212 Major(수정 중) · SHOP-210+198 배송비 반복)
  - SHOP-205는 수정 확인 후 종료

## 담당별 할 일

- **회귀 TC 관리자**: RG-0011 답이 '거부'면 RG-0011 기대 결과를 고친다(기존 케이스 고치기). '보유분까지'면 결함 — 버그 리포터로 등록; SHOP-212 운영 결함 회귀 편입 후보 — 승인 받아 넣기(수정 완료 뒤); SHOP-210 운영 결함 회귀 편입 후보 — 승인 받아 넣기; SHOP-201 운영 결함 회귀 편입 후보 — 승인 받아 넣기
- **기획**: RG-0011 보유 포인트보다 많이 입력하면 보유분까지 자동 사용(기존)인가, 거부(QA 서버 명세)인가?
- **개발**: RG-0018 버그 리포터로 지라 등록(결과 시트 Fail 행) → 수정 → RG-0018 재실행. SHOP-201 케이스(부분 취소 후 나머지 취소)도 함께 확인; RG-0018 쿠폰 복구 작업이나 SHOP-201 수정에서 전체 취소 시 포인트 복구가 빠졌는지; RG-0020 부분 취소 환불에서 무료배송 기준 미달 시 배송비를 빼는 로직이 이번 빌드에 그대로 있는지(QA 서버에서 확인 가능한지)
- **회귀 자동화 관리자**: RG-0020 개발 답이 '로직 있음·QA 서버에서 확인 불가'면 RG-0020을 수동으로 바꿀 후보로 넘기고 스테이지에서 수동 확인. '로직 없음'이면 결함으로 버그 등록
- **테스터**: RG-0001, RG-0009, RG-0012, RG-0013, RG-0015, RG-0016, RG-0021, RG-0022, RG-0025 결과 없는 9개 실행(결과 시트에 기록)
