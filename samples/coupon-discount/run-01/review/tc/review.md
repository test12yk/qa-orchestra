# 장바구니 쿠폰 할인 실행 전 TC 검토

**실행 시작 가능** — 요구사항 18개·충돌 6개·고위험 5개가 모두 TC로 이어져 실행을 시작해도 됨 — 조합·범위 보완 5건은 실행과 함께 진행

- 가정에 기댄 TC가 32개(51%)라, Q1·Q2·Q4·Q9 답을 실행 전에 받으면 다시 판정할 일이 크게 줄어듦(21개)
- 고위험 '부분 취소 환불 금액'은 Q8 답이 없어 지금은 합계 상한(TC-048)만 확인 가능

## 보완 요청 (담당별)
### 기획 분석가
- [중] F-05 분석서 질문에 '적용 후 결제 전 만료 시 결제 허용 여부'를 추가하고, 답에 맞춰 TC 작성 요청 (REQ-14, REQ-17, TC-062)
### 신규 TC 작성가
- [중] F-02 Q8 답이 오는 즉시 상품별 부분 취소 환불액 TC(상품 A·B 각각, 배송비 포함 여부) 추가 (부분 취소 환불 금액, Q8, TC-048)
- [중] F-03 정액 5,000원 쿠폰+포인트 2,000P 주문 전체 취소 → 환불 금액·포인트 잔액·쿠폰 AVAILABLE을 함께 보는 TC 추가 (REQ-15, 포인트 사용(차감 순서·금액), TC-058, TC-060)
- [중] F-04 한도에 걸리는 정률 쿠폰 vs 한도보다 큰 정액 쿠폰(예: 12,000원)의 자동 선택·목록 순서 TC 추가(Q2 가정 표시) (REQ-09, REQ-10, REQ-06, TC-030, TC-033)
- [하] F-06 not_covered의 REQ-18 사유를 '상세 정산 검증만 제외, 금액 불변은 TC-063'으로 분명히 하거나 한쪽으로 정리 (REQ-18, TC-063)
### 기획·정책 담당(답변)
- [중] F-01 실행 전에 Q1·Q2·Q4·Q9 답을 먼저 받기(물어볼 곳은 분석서 질문표) (Q1, Q2, Q4, Q9)

## 지적사항

| 심각도 | 번호 | 분류 | 대상 | 내용 | 담당 |
|---|---|---|---|---|---|
| 중 | F-01 | 판정 보류 예방 | Q1, Q2, Q4, Q9 | 임시 가정에 기댄 TC가 32개이고, 그중 21개가 Q1(배송비 포함)·Q2(한도 기준)·Q4(복구 규칙)·Q9(할인 대상에 배송비)에 걸림. 답이 가정과 다르면 기대 결과가 바뀌어 다시 판정해야 함 | 기획·정책 담당(답변) |
| 중 | F-02 | 위험 커버 약함 | 부분 취소 환불 금액, Q8, TC-048 | 고위험 영역인데 확인 TC는 TC-048(환불 합계 ≤ 48,000원) 하나뿐. 상품별 환불액(쿠폰 할인 안분)은 규칙이 없어 판정 보류로만 남음 | 신규 TC 작성가 |
| 중 | F-03 | 조합 부족 | REQ-15, 포인트 사용(차감 순서·금액), TC-058, TC-060 | 쿠폰+포인트를 함께 쓴 주문의 전체 취소가 없음. TC-058은 쿠폰 없음, TC-060은 쿠폰만 — 이때 현금 환불액·포인트 반환·쿠폰 복구가 한꺼번에 맞는지 확인하는 TC가 없음(포인트 사용은 직접 영향 기능) | 신규 TC 작성가 |
| 중 | F-04 | 조합 부족 | REQ-09, REQ-10, REQ-06, TC-030, TC-033 | 자동 선택·정렬이 '실제 할인액' 기준인지가 중위험인데, 제외 상품이 섞인 경우(TC-030)만 있고 정률 한도에 걸린 경우는 없음. 예: 상품 150,000원이면 정률 10%는 15,000원이 아니라 한도 10,000원 — 이보다 큰 정액 쿠폰이 있을 때 무엇이 선택·위로 정렬되는지 | 신규 TC 작성가 |
| 중 | F-05 | 범위(질문 누락) | REQ-14, REQ-17, TC-062 | 쿠폰을 적용한 뒤 결제 전에 유효기간이 지나는 경우(예: 23:59 적용, 00:00 결제)가 문서·질문에 없음. USED 전환이 승인 시점이라 만료 쿠폰으로 할인 결제가 될 수 있음 | 기획 분석가 |
| 하 | F-06 | 표기 정리 | REQ-18, TC-063 | REQ-18이 not_covered(제외)에도 있고 TC-063(정산 기준 금액 불변)에도 연결돼 있어 커버 여부가 헷갈림 | 신규 TC 작성가 |

## 검토 후 지적에서 뺀 자동 점검 후보
- REQ_NO_BOUNDARY (REQ-03): 숫자는 '1장'·오류 코드 409일 뿐 범위 조건이 아님. 2장째 적용 거부는 TC-014~016이 확인
- REQ_NO_BOUNDARY (REQ-05): 10%·5,000원은 쿠폰 종류 예시라 경계 조건이 아님. 한도·최소 결제액 경계는 REQ-06·08 TC가 확인
- RISK_NO_TC (쿠폰 동시 사용): 낱말이 달라 자동 연결만 안 됐을 뿐 TC-043(동시 결제)·TC-044(다른 주문에서 먼저 USED)가 위험 설명(승인 전 틈, 409는 같은 주문만 막음)을 그대로 확인
- PRIORITY_INFLATED (P1): 팀 기준(P1 = 결제·금액 계산 오류)대로 매겨졌고, 이 기능이 금액 계산 위주라 비율이 높음. 기준 위반 없음
