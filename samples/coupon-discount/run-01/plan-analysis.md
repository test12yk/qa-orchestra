## 1. 기능 요약
- 목적: 첫 구매 전환율 개선을 위해 주문서에서 보유 쿠폰을 쓸 수 있게 한다.
- 대상: 쿠폰을 보유한 회원(주문서 진입 사용자)
- 핵심 흐름: 주문서 진입 → 최대 할인 쿠폰 자동 선택(변경 가능) → 쿠폰 할인 → 포인트 차감 → 결제 승인 → 쿠폰 USED → 취소 시 조건부 복구
- QA 핵심: 최소 주문 금액 판정, 정률 한도·절사·최소 결제액, 쿠폰 동시 사용, 취소(전체·부분·만료) 시 복구

## 3. 문서 간 충돌
### C1 최소 주문 금액에 배송비 포함 여부 (REQ-01) → 충돌 → Q1
- 기획서: 상품 금액 합계 30,000원 이상, 배송비 제외 (기획서 2절(p.3))
- 정책: 쿠폰 적용 전 주문 금액(배송비 포함) 30,000원 이상 (정책 1항)
- 개발: totalPrice(상품 금액+배송비) >= 30000 (API 검증 로직)
### C2 정률 쿠폰 할인 한도: 일괄 값 vs 쿠폰별 설정값 (REQ-06) → 충돌 → Q2
- 정책: 정률 쿠폰 할인 한도 최대 10,000원(일괄) (정책 3항)
- 개발: min(대상금액 × rate, maxDiscount), maxDiscount는 쿠폰별 설정값 (API 할인 계산)
### C3 계산 순서(쿠폰→포인트) vs 화면 표시 순서(포인트→쿠폰) (REQ-13) → 표시 순서 불일치 → Q3
- 기획서: 쿠폰 할인 → 포인트 사용 순서 (기획서 4절(p.5))
- 디자인: 결제 요약에 포인트 사용(-2,000원)이 쿠폰 할인(-5,000원) 위에 표시 ()
- 슬랙: 11/04 박기획(PM): 기획서대로 쿠폰 먼저, 그다음 포인트 ()
### C4 주문 취소 시 쿠폰 복구 범위(전체·부분 취소) (REQ-15, REQ-16) → 충돌·문서 미반영 → Q4
- 기획서: 주문 취소 시 쿠폰 즉시 복구(조건 없음) (기획서 5절(p.6))
- 개발: 전체 취소 시에만 AVAILABLE 복구, 부분 취소는 복구 안 함 (API 쿠폰 상태 변경)
- 슬랙: 11/05 박기획(PM): 부분 취소는 복구 안 함, 기획서는 나중에 업데이트 (문서 미반영) ()
### C5 최소 주문 금액 계산에서 제외 카테고리 상품 금액 차감 여부 (REQ-02, REQ-04) → 충돌 → Q5
- 정책: 혼합 장바구니는 제외 상품 금액을 최소 주문 금액 계산에서도 뺀다 (정책 4항)
- 개발: 최소 금액 검증은 totalPrice(상품+배송비) 전체, 제외 카테고리는 할인 계산에서만 제외 (API 검증 로직)
### C6 취소 시점에 만료된 쿠폰의 복구 여부 (REQ-17) → 슬랙 결정 미반영 → Q4
- 기획서: 주문 취소 시 쿠폰 즉시 복구(만료 예외 없음) (기획서 5절(p.6))
- 개발: 만료 쿠폰 처리 언급 없음 (API 쿠폰 상태 변경)
- 슬랙: 11/05 박기획(PM): 취소 시점에 유효기간 지난 쿠폰도 복구 안 함 (문서 미반영) ()

## 8. 준비 사항
- **테스트 계정**: 쿠폰 여러 장(정률·정액) 보유 회원; 쿠폰 + 포인트 보유 회원; 쿠폰 없는 회원
- **쿠폰 데이터**: 정률 10% 쿠폰(maxDiscount 10,000원 / 10,000원 초과 설정값); 정액 5,000원 쿠폰; 할인액이 같은 쿠폰 2장; 만료 D-3·D-2·D-1·D-0 쿠폰; 취소 시점 직전에 만료되는 쿠폰
- **상품·장바구니**: 배송비 유료 상품(예: 상품 27,000원 + 배송비 3,000원 경계); 상품 29,999원 / 30,000원 경계; 상품권·e쿠폰 카테고리 상품 + 일반 상품 혼합; 정률 한도 경계(예: 100,000원 이상 상품); 결제 금액이 100원 근처가 되는 저가 상품
- **환경·도구**: 테스트 PG(승인 성공·실패·지연 재현); 동시 요청 도구(같은 쿠폰 두 주문 동시 결제); API 직접 호출 도구(409 확인); 쿠폰 상태 조회 권한(DB 또는 관리자)
- **일정 위험**: 기획서 v1.0이 슬랙 결정(11/05) 미반영; API 설계 v0.3 초안 단계, 변경 가능; Q1·Q2·Q4·Q5 답 지연 시 P0 TC 기대 결과 재작업
